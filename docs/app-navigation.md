# 앱 메뉴와 전용 팝업 — 2026-10-24

사용자가 파일 로딩·장치 연결의 앱다운 구분과 별도 팝업을 허용했다. 기존 Spotify 디자인과 단일 Electron 창을 유지한다.

## 구성과 선택

전체를 여러 독립 창으로 나누면 연결 소유권·작업 상태를 창 사이에 공유해야 한다. 모든 도구를 계속 노출하면 편집 영역이 좁아진다. 단일 작업 창과 목적별 모달을 선택한다. 별도 OS 창은 이번 범위 밖이다.

- 파일·공유: JSON 열기, 현재 키맵 내보내기, 공유 링크. 실제 파일 선택은 기존 OS 선택기 사용.
- 키맵: 내 보관함과 카탈로그. 새 키맵·저장은 편집 화면과 네이티브 메뉴에 제공.
- 장치 관리: 연결 방식, 연결·해제, 장치 모델/상태, 설정 읽기, 장치 백업, 상태·LED. 연결 여부와 작업 중 잠금을 유지.
- 편집 화면: 프로필 이름·저장, 모델·방향, 레이어·키보드, 동작 편집, 연결 요약·적용.
- macOS 메뉴: 파일 / 편집 / 키맵 / 장치 / 보기. 네이티브 메뉴에서 renderer로 보내는 작업은 고정 목록만 허용한다. OS 메뉴는 화면의 팝업·기능을 재사용한다.

색은 기존 #121212/#181818/#242424 바탕, #fff/#b3b3b3 텍스트, #1ed760 적용 강조. 기존 시스템 서체와 크기 계층 유지. 연결 팝업은 키보드 도형과 상태 점으로 장치를 보여주고, 설명은 상태와 오류에 한정한다.

## 실행 및 검증

1. 고정 메뉴 작업 목록과 테스트 추가.
2. 파일·장치 팝업을 만들고 중복 도구를 옮긴다. 기존 백업·쓰기·재읽기 경로 보존.
3. main/preload 메뉴 이벤트와 renderer 연결. 모달 전환·busy 상태 확인.
4. 전체 회귀와 네이티브 화면 확인, 패키징·설치 및 저장소 반영.

## 검증 결과

- JavaScript 58개와 Python 27개 통과. 기존 카탈로그·가상 HID 회귀 포함. 독립 리뷰에서 중요 문제 없음.
- 설치 앱 0.3.1에서 ⌘O로 파일·공유 팝업, 파일 열기로 macOS 선택기, 취소 후 ⌘⇧D로 장치 관리 팝업을 확인했다.
- 실제 연결된 USB 키보드의 연결 해제·재연결을 수행했다. 연결 해제 시 설정 읽기·LED 비활성화, 재연결 및 현재 설정 읽기 완료를 확인했다. 키 기록·LED 변경은 수행하지 않았다.
- 기존 다크 워크벤치의 편집기·하단 적용 영역이 창 높이 안에 보이는 것을 네이티브 화면으로 확인했다. 팝업은 Escape와 닫기로 종료할 수 있다.
- 새 파일 형식·HID 프로토콜·독립 OS 창은 추가하지 않았다. 네이티브 메뉴는 기존 화면 기능을 호출하며 직접 장치 기록을 전송하지 않는다.
