# GitHub 키맵 카탈로그

2026-10-24 사용자 요청: 개인 GitHub 저장소를 앱과 카탈로그로 나누고 앱에서 내려받아 적용한다.

## 결정

- 소유자 kyungtaek, 비공개 저장소 mini-keyboard-studio / mini-keyboard-keymap-catalog. 앱 소스와 카탈로그 데이터를 독립적으로 버전 관리한다. 개인 장치 백업·인증·빌드·런타임 증거는 업로드하지 않는다.
- 카탈로그는 catalog.json + keymaps/*.json + 단축키 근거 + 독립 검사 스크립트. 여섯 샘플을 첫 항목으로 제공한다. SHA-256, 모델, 플랫폼, 버전, 설명·태그를 명시한다.
- Electron main만 GitHub API와 통신한다. 기존 gh 로그인 또는 앱에 저장한 읽기 토큰을 사용하고 토큰은 renderer/프로필/로그에 노출하지 않는다. 입력 토큰은 Electron async safeStorage로 암호화한다. 별도 인증 서버나 계정 DB를 만들지 않는다.
- main ref를 commit SHA로 고정한 다음 같은 커밋에서 목록과 프로필을 읽는다. 크기·경로·스키마·해시·모델 메타데이터를 검증한다. 카탈로그를 스크립트/HTML 실행 경로로 사용하지 않는다.
- 검증한 목록과 내려받은 프로필만 앱 데이터에 캐시한다. 네트워크/인증 오류는 숨기지 않고 캐시 사용 상태를 표시한다. 새로 받지 않은 키맵은 오프라인에서 다운로드 성공으로 표시하지 않는다.
- 중앙 작업 화면 높이를 유지하며 왼쪽 카탈로그 버튼에서 검색/플랫폼/모델별 카드 대화상자를 연다. 기존 기본 샘플도 오프라인에서 유지한다.
- 편집기로 열기와 다운로드·적용을 제공한다. 직접 적용은 모델 일치, 장치 연결, 원본 백업, 기존 쓰기/검증/롤백 절차를 통과해야 한다. 사용자의 현재 키맵을 보관하고 새 프로필 ID로 저장한다.

## 검증

두 저장소 private/owner 확인, 원격 실제 목록/6프로필 내려받기, 수정·손상·권한·캐시·임의경로 거부, 새 Electron 설치/카탈로그 화면, 기존 HID 회귀. 실제 사용자의 샘플은 임의로 장치에 적용하지 않고, 쓰기 경로는 모의 장치 및 기존 물리 증거와 구분한다.
