# 기능 선택과 키 LED 편집 — 2026-10-25

키맵에는 앱을 연결하지 않는다. 앱 자동 전환이나 포커스 수집을 수행하지 않으며 장치 쓰기는 명시적인 적용 버튼으로 수행한다.

## 사용 흐름

1. 새 키맵에는 이름과 장치 모델만 지정한다.
2. 오른쪽 기능 선택의 지원 앱 목록에서 시스템 기본, VS Code, Codex, Claude 또는 지원 게임을 선택한다. 이 선택은 편집기 상태이며 키맵에 저장되지 않는다.
3. 키 또는 노브를 누르고 기능을 검색·선택하면 기능 이름과 단축키가 입력된다. 목록을 바꿔도 기존 동작과 이름은 유지된다.
4. 휴지통 버튼은 선택한 키/노브 동작을 disabled로 바꾼다. 원래 동작 유지와 달리 적용하면 해당 슬롯은 입력을 보내지 않는다.
5. 16키 모델의 키 패널 하단에는 고정 16색 팔레트와 LED 모드 선택이 있다. 색은 해당 키, 모드는 레이어 전체에 적용된다. 노브 LED와 다른 모델의 LED는 지원하지 않는다.
6. 저장·내보내기·공유는 LED 편집값도 보관한다. 장치에 적용을 누르면 키를 기록한 다음 LED를 기록하고 각각 재읽어 검증한다.

## 파일 계약

프로필 v4는 applicationId를 제거하고 각 레이어에 lighting을 추가한다. lighting은 null(장치 설정 보존) 또는 {mode:null|0..5,colors:16개 null|팔레트 hex}다. null 항목은 적용 시 현재 장치 값을 유지한다. 명시적으로 선택한 색은 고정 팔레트만 허용한다. 기존 v1~v3 파일은 동작·이름·방향을 보존하며 v4로 변환하고 예전 applicationId를 버린다.

기능 이름은 편집 메타데이터이며 HID 코덱은 label을 전송하지 않는다. 레이어 복사·회전은 이름과 LED 색도 함께 옮긴다. 장치 USB 슬롯은 화면 키 ID와 동일하며 방향은 화면 기하만 조절한다. 키 배치 회전 기능을 명시적으로 선택한 경우에만 동작·색의 슬롯을 재배치한다.

## LED 적용과 검증 범위

키맵 LED는 saveProfileLighting 명령으로 영구 기준값을 갱신하며 정상 종료 후에도 유지한다. 임시 앱 상태 LED 규칙은 기존처럼 종료 시 기준값으로 돌아간다. 배치는 장치 식별자·시리얼을 확인하고 쓰기 전 백업, 쓰기 후 재읽기, 실패 시 직전 값 복원을 수행한다. 키 적용 이후 LED가 실패하면 같은 장치에 한해서 키도 원본 백업으로 복구한다. 키와 LED의 전체 동작이 전원 차단에 대해 원자적인 트랜잭션인 것은 아니다.

원본 앱은 LED 모드를 0~5 번호로만 표시한다. 항상 켜짐·누를 때만 켜짐 등 시각 효과의 이름은 아직 실물 검증하지 않았으므로 번호를 그대로 노출한다. 프로토콜 재읽기 일치는 시각 효과나 전원 재연결 후 지속성의 증거가 아니다.
