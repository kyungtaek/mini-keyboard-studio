# 앱 연결과 기능 선택 편집 — 2026-10-24

사용자는 앱 전환 시 장치 자동 적용 대신 앱 연결·기능 목록만 구현하기로 선택했다. 설정 쓰기·검증은 계속 명시적인 적용 버튼으로 수행한다. 앱 포커스 수집기나 자동 HID 쓰기를 추가하지 않는다.

## 사용 흐름

1. 내 키맵의 + 또는 ⌘N으로 이름·연결 앱·장치 모델을 지정한다. 앱을 지정하지 않으면 시스템 기본이다.
2. 연결 앱은 작업 화면의 선택기로 바꾼다. 오른쪽 기능 선택 목록도 해당 앱으로 전환한다.
3. 키 또는 노브를 누르고 기능을 검색·선택하면 해당 슬롯에 기능 이름과 단축키가 입력된다. 장치 쓰기는 하지 않는다. 직접 입력 탭으로 조합·매크로·미디어를 계속 편집할 수 있다.
4. 화면의 키에는 기능 이름과 조합을 함께 표시한다. 앱 기능 목록은 기존 검증 출처 데이터를 사용하며, 게임 제안과 선행 설정이 필요한 기능은 구분한다.
5. 사용자가 저장·내보내기·공유하면 연결 앱과 기능 이름도 보관한다.

## 파일 계약

프로필 v3는 v2에 nullable `applicationId`를 추가하고 동작에 optional `label`(최대 80자)을 지원한다. v1/v2는 변환해서 읽으며, 기존 여섯 샘플은 알려진 ID로 앱을 연결한다. 시스템 샘플·그 밖의 기존 사용자 키맵은 앱 연결을 추정하지 않는다. 알 수 없는 앱 ID는 임의 경로를 fetch하지 않고 선택 지원 여부를 표시한다.

기능 이름은 편집 메타데이터다. HID 코덱은 기존 키/매크로/미디어 데이터를 사용하며 label을 전송하지 않는다. 수동 입력으로 동작을 바꾸면 이전 label을 제거한다. 앱 연결을 변경할 때도 이전 label을 지워 다른 앱의 기능명이 그대로 남지 않게 한다. 레이어 복사·회전은 action과 label을 함께 옮긴다. 저장 확인 여부는 기능명이 아닌 실제 키 조합으로 판단한다.

카탈로그 저장소의 검증기도 v3를 지원한다. 기존 여섯 JSON과 manifest 해시는 그대로 유지한다. 구버전 앱으로 v3 파일을 읽는 것은 지원하지 않는다.

## 설치 검증

0.4.0 앱에서 새 키맵 생성 시 기본값이 시스템 기본임을 확인하고, Visual Studio Code 연결 키맵을 만들어 기능 검색 → 명령 팔레트 선택 → 키 01 기능명·조합 표시 → 내 키맵 저장 → 직접 입력 탭의 SHIFT+META+P 확인까지 수행했다. 장치 쓰기는 수행하지 않았다. 기존 Codex 작업은 별도 보관했다.

0도 초기화 확인창의 화면 방향만 변경 분기도 확인했다. 로그 파일에 앱 버전·동작 읽기 단계가 저장되는 것을 확인했다. 디스크 부족 시 진단용 상태 파일 쓰기 실패가 주기 상태 갱신의 미처리 rejection으로 번지지 않도록 보완했다.
